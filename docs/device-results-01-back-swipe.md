# 实测记录 01 · 右滑返回

- 设备：REDMI Watch 6 普通版（432×514）
- 日期：2026-10-25
- 目标：确认能否关闭"右滑返回"，以及它会不会把应用弹出去

---

## 1. 结论（先看这个）

**最终结论：`followHand: "disable"` 在这台设备上没有任何作用——栈深度 1 和 2 都拦不住右滑。**

| 场景 | 实测结果 |
|---|---|
| 栈深度 2 + 无字段 | 右滑**弹回上一页** |
| 栈深度 2 + `followHand: disable` | 右滑**照样弹回上一页** |
| 栈深度 1 + 无字段 | 右滑**退出应用** |
| 栈深度 1 + `followHand: disable` | 右滑**照样退出应用** |
| 栈深度 1 + `followHand: disable`（第一轮探针） | 当时记录"没退出"，与上一条冲突，判为该次手势没被系统识别，已作废 |

也就是说：

> **右滑返回无法用应用层手段关闭。栈深度 1 会退出应用，栈深度 ≥ 2 会弹回上一层。**

对项目的直接影响：

1. 地图**不能**用横滑做移动——只要栈深度 ≥ 2，横滑就会被系统吃掉；
2. **游戏不能只有一个页面**。单页 = 栈底 = 一滑就退出；
3. 唯一的结构性缓解是**在游戏页下面垫一层**：右滑变成"回到这一层"，而不是"退出应用"；
4. 垫层只能买到一次缓冲——那一层自己是栈底，在上面再右滑仍然退出（已实测）；
5. 无论有没有垫层，**自动存档都是必需的**。

---

## 2. 实验记录

### 2.1 单页包（`probe-followhand-disable.rpk`）

- 包名 `com.probe.followhand`，应用名"右滑测试"，输入探针加 `followHand: "disable"`；
- 只有一个页面，栈深度 1；
- 结果：当时记录为**横滑不返回、不退出**；
- **这个结论已作废**：2.5 的严格 A/B（同代码、只差字段）里，带字段的单页包一样退出。
  最可能的原因是那次手势没有真正落到系统识别区（probe 页面中部有滚动容器），或者观察有偏差。

### 2.2 两页对照包（`glab-1-control.rpk` / `glab-2-followhand.rpk`）

- A → B 两页，栈深度 2；
- 两组除 B 页 `followHand` 外完全相同（已核对：`pages/Index/index.js` 字节一致，`pages/Detail/index.js` 只差标签 1 字节）；
- 结果：**两组右滑都会返回**。

判定：**在栈深度 2 上，这个字段不阻止"弹回上一页"。** 注意限定条件——它不代表字段在所有场景下都无效。

### 2.3 编译级验证

- `aiot-toolkit@2.0.5` 对该字段**不报错**；
- 解包 RPK，`manifest.json` 里**原样保留**；
- 所以问题不在编译，在运行时。

### 2.4 守卫页实测（`guard-demo.rpk`）

- 栈：Guard（栈底）→ Game（深度 2），两页都**不带** `followHand`；
- 从 Game 右滑 → 弹回 Guard，**计数保持不变**；
- 「共享标记」显示 `G Q G`，证明两个页面共享同一份 `globalThis` 状态；
- **在 Guard 上再右滑一次 → 退出应用**。

这条是理解整件事的钥匙：它说明"栈底（深度 1）右滑会退出应用"。而第一轮探针同样是栈底、但带了 `followHand`，却没有退出。

### 2.5 单页 A/B（`guard-flat-control.rpk` / `guard-flat-followhand.rpk`）—— 决定性实验

- 两个包都是单页，`pages/Game/index.js` **字节完全一致**，只有 `manifest.json` 差 `followHand`；
- 结果：**红叉（无字段）退出，青箭头（有字段）同样退出**；
- 判定：**字段在栈底也无效**。2.4 里"单页 + 字段不退出"的解释不成立，2.1 的旧观察作废。

这是整组实验里唯一干净的对照，也是最终结论的依据。

## 4. 下一步：存储与退出恢复

不管最后用哪种返回方案，都要知道"被弹出去时能不能存盘"。工具：`experiments/storage-probe/`，安装包 [`releases/storage-probe.rpk`](../releases/storage-probe.rpk)（应用名"存档探针"，绿色下箭头图标）。

判读方式写在 `experiments/storage-probe/README.md` 里，核心是：重新打开后看四个生命周期打点哪个有时间戳——有 onHide 就能在退出前自动存档，都没有就只能靠关键节点主动存。
